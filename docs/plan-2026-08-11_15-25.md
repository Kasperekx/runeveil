# Plan: Chat + dziennik walki / systemu (WoW / Tibia)

Timestamp: 2026-08-11_15-25

## Cel
Okienko czatu na dole ekranu z kanałami: czat graczy + log walki + łupy + system (notices, XP, questy, craft, mining, handel, śmierć). Teksty po polsku, kolory jak w klasycznych MMO.

## Zasady (KISS / YAGNI / SRP)
- **KISS**: jeden panel DOM (`GameChat`), jedna kolejka linii, filtry zakładek — bez osobnych okien na każdy kanał.
- **YAGNI (v1)**: tylko **Say** (lokalny / mapa), bez whisper / party / guild / emote. Brak resize i historii po F5.
- **SRP**: UI tylko renderuje; formatowanie linii w małym helperze; sieć tylko transportuje zdarzenia.
- **DRY**: istniejące `combatText` / `notice` / `xpGain` / `tradeResult` itd. zasilają log po stronie klienta; nowe wiadomości serwera tylko tam, gdzie dziś brak feedbacku (say, loot).

## UX
- Panel dolny-lewy (nad minimapą / obok HUD — dopasować do istniejącego layoutu), zawsze widoczny w grze.
- Zakładki filtrów: **Wszystkie | Czat | Walka | Łupy | System**.
- Lista przewijana (max ~200 linii, FIFO), auto-scroll gdy użytkownik jest na dole.
- Input: Enter fokusuje / wysyła, Esc odblokowuje ruch; podczas fokusa WASD i hotkeys nie działają.
- Kolory (propozycja): czat = biały, walka dmg = żółty/krem, otrzymany = czerwony, heal = zielony, XP = fiolet, loot = złoty, system = szary/pomarańcz.

## Źródła zdarzeń

### Klient (bez zmian protokołu)
- `combatText` → „Zadajesz X pkt obrażeń (Nazwa)” / „Nazwa zadaje Ci X” / „Odzyskujesz X HP”
- `xpGain`, `levelUp`
- `notice` (+ istniejące `NOTICE_COPY`)
- `tradeResult`, `equipmentRepaired` / `Broken`
- `playerDied` / `playerRespawned`
- `professionCrafted`, `oreMined`
- quest accepted / claimed / ready (krótka linia)

### Serwer (nowe)
1. **`chat`** — klient `send("chat", { text })`; serwer waliduje (trim, max ~120 znaków), broadcast do graczy **na tej samej mapie** (opcjonalnie zasięg ~radius YAGNI: mapa wystarczy). Payload: `{ playerId, name, text, mapId }`.
2. **`lootReceived`** — po udanym `lootCorpse` / `lootAllCorpse` / `collect`: `{ itemId, quantity, source?: "corpse"|"ground"|"other" }` (oraz ewentualnie lista przy loot-all).

### Opcjonalne wzbogacenie combatText (małe)
- Przy hitach dodać `sourceName` / `targetName` albo `creatureKind`, żeby log nie zależał od lokalnego lookupu pozycji zwierzęcia. Preferencja: dodać `creatureKind` + klient i tak zna własne imię.

## Pliki (szacunek)
- `src/ui/GameChat.ts` — panel + input + filtry
- `src/ui/chatLogFormat.ts` — czyste funkcje PL formatujące linie
- `public/style.css` — styl panelu w tonie quest-log / HUD
- `src/network/GameNetwork.ts` — `sendChat`, `onChat`, `onLootReceived`
- `src/game/Game.ts` — podpięcie handlerów + blokada inputu
- `src/input/KeyboardInput.ts` — ignoruj gameplay keys gdy aktywny element to input/textarea
- `server/src/rooms/WorldRoom.ts` — handlery `chat` + `lootReceived`

## Poza zakresem v1
- Whisper / party / guild
- Log walki innych graczy w zasięgu
- Zapisywanie historii, ustawienia filtrów w localStorage (można dodać później tanio)
- Osobne floating numbers (zostają jak są)
- Moderacja / ban na chat (prosty max length + strip control chars wystarczy)

## Krytyka planu
- Routing wielu istniejących eventów → chat jest OK; nie duplikujemy toastów (toast zostaje na krótkie błędy, chat dostaje też linię systemową gdzie ma sens).
- Say tylko na mapie: proste i wystarczające dla small MMO.
- Bez persistence: akceptowalne; log to ephemeral feedback.
